# Event Pack Factory 与 AI 引导说明

Event Pack Factory 用于把多份网页原文或联网发现的公开来源整理成一个**待人工审核**的 Event Pack。它解决“来源很多、手动逐项抄写困难”的问题，但不会替用户判断事实、自动冻结事件包或直接开始实验。

本功能仍遵守 EventShock Lab 的核心边界：

- 搜索摘要不是证据，模型提取的主张也不是已确认事实。
- 来源、时间、候选主张、Event Pack 冻结、单一干预和实验提交都保留明确的人类门禁。
- 市场价格、订单簿、流动性、Agent 行为与反事实结果仍是模型内情景，不是现实预测或投资建议。

## 两种入口

### 专家模式

专家模式直接进入 Event Pack Factory、事件包审核和情景配置页面。适合愿意自行填写来源元数据、时间边界、证券代码、主张数量、影响渠道与实验参数的研究人员。

Factory 支持两种来源收集方式：

1. **批量粘贴**：逐份填写标题、发布者、可选 HTTPS URL、发布时间、`knownAt` 和网页原文。
2. **联网发现**：使用智谱 Web Search 找到候选网页，再由智谱 Reader 从批准的候选 URL 读取完整正文。

### AI 引导模式

AI 引导模式面向首次使用者，以持久化的有界工作流分阶段收集信息：

1. 研究事件与目标；
2. 来源收集方式；
3. 来源审核；
4. 候选主张审核；
5. Event Pack 元数据审核；
6. Event Pack 冻结确认；
7. 单一情景干预；
8. 情景审核；
9. 运行前检查；
10. 提交准备与完成。

每一轮 AI 只能返回当前阶段允许的严格结构，例如事件元数据、来源方式、最多四条搜索问题或一个白名单干预变量。“应用建议”只把提议复制到引导草稿；它不调用搜索、不创建或冻结 Event Pack、不创建情景，也不提交实验。需要实际操作时，界面会把用户带到对应的专用审核页面。

注册后的模式推荐来自用户自报的经验、期望协助程度和使用目标，不是能力考试或风险评分。用户可以不采用推荐，并在之后切换模式。

## 批量粘贴流程

1. 创建一个 Factory 构建并填写便于识别的名称。
2. 为每份来源填写独立元数据和原文。不要把多个网页混进同一个来源字段。
3. 提交前确认自己有权保存该内容，并有权在启用 AI 时把必要片段发送给所选供应商。
4. 系统先运行确定性内容安全扫描。高风险内容在落库或外部模型调用前阻断；需要复核的内容必须由人确认并按提示脱敏。
5. 逐份检查标题、发布者、时间、摘要和原文核验引文，选择批准或拒绝。
6. 只有已批准的 `PASTE` 来源可以进入物化。

单个原文最多 100,000 个字符；每个构建最多保留 24 个未拒绝的证据来源，保留原文总量最多 400,000 个字符。前端可能把一次批量输入拆成更小批次，这不会放宽后端总上限。

## 联网发现与 Reader 流程

联网流程故意分成两个独立的人类门禁：

```text
Web Search
  -> 发现记录（SEARCH_RESULT，DISCOVERY_ONLY）
  -> 人工批准候选 URL
  -> Reader 读取该公开 HTTPS 页面
  -> 新证据来源（READER，PENDING）
  -> 人工单独批准 Reader 正文
  -> 允许进入 Event Pack 物化
```

Search 保存标题、规范化 URL、发布者、时间、有限摘要、查询哈希、供应商 Request ID、参数和估算费用等发现元数据。它不会把搜索摘要保存为证据原文，也不会允许 `SEARCH_RESULT` 支撑候选主张或冻结。

用户批准发现记录后，服务器只允许把该记录中经过规范化的公开 HTTPS URL 发送给智谱 Reader。应用自身调用固定供应商端点时不跟随该端点的 HTTP 重定向，并会在发送前拒绝私有、回环或其他非公开目标；但目标网页实际抓取发生在供应商侧，供应商内部的 DNS 解析和网页重定向行为不由本应用完全验证。取得的正文仍要经过内容安全扫描，并以新的 `READER` 证据来源进入待审核状态。

不能省略第二次审核：批准搜索结果只表示“值得读取”，不表示已批准 Reader 返回的正文。

## 来源状态与原文存储

| 来源类型 | 作用 | 是否保存内部原文 | 能否支撑主张 |
| --- | --- | --- | --- |
| `PASTE` | 用户粘贴的完整来源 | 是，待审核或已批准期间保留 | 仅人工批准后可以 |
| `SEARCH_RESULT` | 搜索发现记录 | 否，只保存有限发现元数据与摘要 | 永远不可以 |
| `READER` | Reader 获取的完整网页来源 | 是，待审核或已批准期间保留 | 仅人工批准后可以 |

`PASTE` 与 `READER` 原文保存在按 `ownerUserId + buildId + sourceId` 隔离的内部 SQLite payload 表。普通构建快照和来源响应只返回内容哈希、长度、审核状态与有限审核信息。来源 owner 可在审核卡片中显式展开，通过 `Cache-Control: no-store` 的专用接口按需读取完整原文；该接口不会把原文写入审计详情。原文不会进入普通日志、搜索记录或导出包。

原文保留是为了让稍后的来源审核和 Event Pack 物化仍可执行。它不是长期文档仓库，也不代表 EventShock Lab 获得了内容的再分发许可。

每个 Factory 构建从最近一次实质修改起暂存 **7 天**，API 会返回明确的 `retentionExpiresAt`。新增来源、审核、搜索、Reader、原文修订等会顺延到期时间；仅查看构建或原文不会顺延。到期构建在下一次 Factory 请求时自动清除，已经物化的 Event Pack 不受影响。数据库备份和主机快照仍受部署方自己的保留政策约束。

owner 可以修订尚有正文的 `PASTE` 或 `READER` 来源。保存修订会创建新的构建 revision、重新运行安全扫描、把来源强制重置为 `PENDING`，并清除未重新提交的旧摘要与核验引文；先前批准不能跨正文修订继承。审计只记录旧/新哈希、长度、安全判定和 revision，不记录正文。

### 拒绝来源

拒绝 `PASTE` 或 `READER` 证据来源是终态操作：

- 删除内部原文；
- 清除审核摘要与核验引文；
- 保留最小来源身份、内容哈希、长度、拒绝状态和时间等非正文记录，以维持版本与审核一致性；
- 启用 SQLite `secure_delete`，并在删除提交后**尝试**截断 WAL，减少已删除正文继续停留在数据库历史帧中的机会；checkpoint 失败不会回滚已经完成的删除。

被拒绝的来源不能重新批准。如需重新提交，应创建新的来源记录。

### 删除 Factory 构建

“删除构建和原文”会永久删除当前账号拥有的：

- 全部内部来源原文；
- 来源与父子关系；
- 搜索记录及发现元数据；
- 审核状态和构建本身；
- 相关 SQLite WAL 历史帧会在删除后尝试截断。

该操作不会追溯删除已经物化出的 Event Pack。物化后的 Event Pack 只保留来源元数据、内容哈希、时间、短证据引文和候选主张，不保留 Factory 完整原文。若还需删除其他账号研究对象，应使用对应对象自身提供的删除或保留策略，不能把“删除 Factory 构建”理解为全账号级擦除。

数据库备份、主机快照或供应商侧处理可能有各自的保留周期；应用内删除不能替代组织层面的备份和第三方数据治理政策。

## 收费与创建操作的幂等

Search、Reader 和物化请求都要求浏览器生成 `clientRequestId`，服务器同时保存规范化请求体的 SHA-256。相同账号、操作、请求号和完全相同的 payload 会恢复首次成功结果，不再次调用供应商或重复创建 Event Pack；相同请求号配不同 payload 会返回冲突。浏览器超时或网络中断后，未修改请求的重试复用原请求号。

若服务在供应商可能已经接收请求、但成功终态尚未写入前失败，记录会停在未知结果状态；同一请求号不会自动重新调度，以避免隐性重复计费。用户必须核对供应商控制台，再通过修改请求或明确发起新请求来获得新的请求号。

## 物化、主张审核与冻结

物化前至少需要一个人工批准且仍保留原文的 `PASTE` 或 `READER` 来源。物化会：

1. 再次核对构建 revision，防止并发页面用旧状态覆盖新审核；
2. 读取仅供后端内部使用的批准来源原文，并校验长度与 SHA-256 哈希；
3. 执行 Event Pack 级内容安全检查；
4. 使用规则提取或当前会话已配置的结构化模型提取候选主张；
5. 创建新的 `DRAFT` Event Pack。

所有自动提取主张初始状态都是 `AI_PROPOSED`。用户必须逐条批准、编辑或拒绝；一键批准也要求先经过明确警告确认。仍有 `AI_PROPOSED` 主张时不能冻结，必要主张没有被批准或编辑时同样不能冻结。Factory 本身永远不会自动冻结 Event Pack。

## 高级模型参数

AI 配置支持有限的供应商参数自定义：`temperature`、`topP`、`presencePenalty`、`frequencyPenalty`、`seed` 和 `timeoutSeconds`。服务端会同时校验固定范围与供应商能力矩阵；供应商不支持的字段会被拒绝。

产品有意不开放任意 Base URL、请求头、工具定义、system prompt 或自由 JSON 请求体。这样既避免把 API Key 发送给未授权主机，也防止绕过证据、动作、费用和结构化输出边界。详细范围见 [AI 供应商接入说明](ai-providers.md)。

## 提示词注入与人工责任

系统提示词随源码可被审阅，安全设计不依赖隐藏提示词。外部正文、搜索摘要和历史对话只会进入明确分隔的不可信数据区；模型输出还必须通过严格 Schema、证据/动作/时间白名单、提示词片段与凭据泄漏检测、一次有限修复和失败关闭。

这些措施无法证明模型完全不会受提示词注入影响。实际使用时仍应：

- 不上传 API Key、密码、券商凭据、受监管个人数据或私人通信；
- 不把网页中的“忽略此前指令”等文本当成可信命令；
- 核对发布者、URL、发布时间、`knownAt` 与逐字证据引文；
- 把模型输出视为待审核草稿，不因语言流畅而降低证据标准；
- 在冻结前重新检查每条保留主张与来源的对应关系。

确定性内容扫描器不是反病毒沙箱、完整网页取证工具或法律合规服务。内容许可、个人信息处理、供应商数据政策与组织保留义务仍由使用者和部署方负责。
