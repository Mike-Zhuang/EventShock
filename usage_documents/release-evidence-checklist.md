# EventShock 发布证据与外部门禁清单

本清单用于记录无法仅靠代码提交证明的生产发布条件。任何人都不得因为“功能已经写完”而把下列项目标记为通过；只有取得对应的直接证据后，才能由负责人填写状态、时间和证据位置。

## 状态定义

- `NOT_STARTED`：尚未执行。
- `IN_PROGRESS`：正在执行，但证据不完整。
- `PASS`：已取得本清单要求的直接证据。
- `FAIL`：已执行但未满足门禁。
- `NOT_APPLICABLE`：经负责人书面说明后确认不适用。

证据中不得保存密码、API Key、验证码、完整会话 Cookie、授权头、SMTP 凭据或来源全文。日志片段必须先脱敏。

## 1. 长期凭据轮换

初始状态：`NOT_STARTED`

必须分别轮换：

- 发件邮箱 SMTP 授权凭据；
- 管理员账号密码；
- 曾在聊天、截图、终端历史或非受控文档中出现的其他长期凭据。

通过条件：

1. 旧凭据无法再认证；
2. 新凭据只存在于服务器受限环境变量或密钥管理设施中；
3. 仓库当前内容与 Git 历史秘密扫描通过；
4. 应用日志、部署日志、宝塔任务日志和导出包抽样检查无凭据；
5. 邮件验证码、管理员登录和密码重置使用新凭据完成最小冒烟测试。

## 3. 目标用户 UAT

初始状态：`NOT_STARTED`

至少邀请三位具有不同背景的目标用户，覆盖至少两个用户群，并且至少包含一位自主研究型个人投资者。其他参与者可来自市场风险分析、机构研究、复杂系统/市场结构研究或相关教学。目标用户由“希望理解市场事件风险传播”这一共同任务定义，不再以机构身份作为准入条件。

每位参与者使用全新账号，在不接受团队口头操作提示的情况下完成：

1. 理解产品面向希望研究市场事件风险的人；个人投资者和专业分析人员都可以使用，但它是情景研究工具，不是确定预测、个性化荐股或自动交易服务；
2. 创建或选择 Event Pack；
3. 审核来源和主张；
4. 配置恰好一个干预变量；
5. 理解规则模式与混合 LLM 模式；
6. 完成运行前复核并启动实验；
7. 读出主要指标、经验区间和至少一个局限；
8. 追踪一条机制链路；
9. 导出可复现包；
10. 找到账户数据导出与删除入口。

通过门槛：

- 3/3 能在 20 分钟内完成核心闭环；
- 3/3 能正确回答“这是情景分析还是预测”；
- 3/3 能指出当前实验的单一干预；
- 3/3 能区分“情景内方向性含义”与“基于个人情况的交易指令”；
- 至少 2/3 无需帮助即可找到主要结果、局限和导出；
- 所有阻塞性问题均已进入 Issue 或有明确修复提交。

## 4. 受控主机重启与代理链验证

初始状态：`NOT_STARTED`

该项只能在维护窗口执行。课堂演示、正在运行的实验或未经负责人确认的时间段内，不得为了“补证据”直接重启生产主机。

重启后必须取得以下直接证据：

- Docker 和应用容器自动恢复；
- 宝塔 Nginx 在 Docker 就绪后启动，systemd drop-in 生效；
- Caddy 启动门控按顺序验证应用和宝塔代理；
- 公网 `/api/health` 返回 `status=ok` 和预期 40 位发布 SHA；
- API 认证、事件包读取和实验历史最小冒烟测试通过；
- 宝塔站点 access log / 流量统计在一次真实公网请求后增长；
- 宝塔“EventShock GitHub 自动同步部署”任务仍存在、启用且日志可读；
- 没有把应用端口 `18000` 或内部 Nginx 端口 `18080` 暴露到公网。

## 5. 模型与搜索能力验证矩阵

供应商存在于配置目录不等于已通过本项目测试。每个可选择模型都应记录：

| 供应商 | 模型 | 真实项目 Key | 严格 JSON | 流式文本 | 思考兼容性 | 价格快照日期 | 结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Zhipu | GLM-5.2 | 待填写 | 待填写 | 待填写 | 严格 JSON 强制关闭思考 | 待填写 | 待填写 |

未通过真实项目 Key 验证的供应商或模型，前端必须保留“未经本项目测试”的警告。不得把社区文档、供应商营销页或单次普通聊天成功当作结构化工作流通过证据。

### Reader 供应链安全确认

EventShock Lab 只对用户提交的 Reader URL 执行静态边界检查：必须是无凭据、端口为
443 的公开 HTTPS 形式，并拒绝明显的 localhost、私网、link-local、保留地址和歧义
IP 写法。目标网页的 DNS 解析、实际连接和网页重定向由智谱 Reader 服务执行，应用
无法对供应商网络中的每一跳重新解析、校验或固定 IP。因此，完成代码检查并不等于
已经验证供应商侧 SSRF 防护。

上线 Reader 前还需记录：

```text
状态：
供应商安全/合规文档版本：
供应商是否承诺阻止私网、link-local 和云元数据地址：
供应商是否在每次重定向后重新校验目标：
供应商安全响应或工单证据：
本项目静态 URL 边界测试提交 SHA：
Reader 返回来源身份人工复核记录：
接受的剩余风险与负责人：
```

在该证据不完整时，治理状态必须保持 `IN_PROGRESS`；界面必须明确显示“供应商代抓取，
应用未执行 DNS 固定与逐跳验证”，不得描述为“已完全通过本地 SSRF 校验”。
