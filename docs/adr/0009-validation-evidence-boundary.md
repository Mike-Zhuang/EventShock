# ADR 0009：验证结果按机器证据与人工证据分层

- 状态：当前 MVP 已接受
- 日期：2026-07-15
- 负责人：EventShock Lab 工程团队

## 背景

单元测试能证明 Schema、边界和确定性属性，却不能证明用户理解、金融含义有效、来源权威或安全审查完成。如果把文档存在、测试通过或 AI 自评当成人工批准，会产生虚假的发布信心。

## 决策

验证记录明确区分自动化测试、人工用户研究、领域专家评审、安全评审、法律或许可评审。P0 发布门要求真实人工证据的项目，只有在提供工件 URI、SHA-256、带时区采集时间、真实评审者姓名与角色以及明确证明语句时才能标记为 VERIFIED。AI、自动化脚本或本仓库文档不能冒充人工评审；缺失时统一标记 `PENDING_HUMAN_EVIDENCE`，并阻塞正式发布判断。

## 被否决的方案

- 测试全绿即允许正式发布：测试没有覆盖真实用户理解与领域有效性。
- 以团队口头声明替代审计工件：无法复核，也容易随时间丢失。
- 由 LLM 给自身安全性打分并批准：存在明显利益冲突且缺少独立证据。

## 后果

发布状态更诚实，机器可验证内容与需要人类判断的内容不会混淆。代价是正式门禁可能长期保持阻塞，直到团队完成真实研究、评审和演练；这不会阻止明确标注为课堂原型的本地开发与受控演示。

## 验证与复审

发布门代码应拒绝不完整或伪造的人类证据，并对任何未通过 P0 项返回 BLOCKED。用户研究、领域专家、模型验证、安全、许可证和事故演练当前均为 `PENDING_HUMAN_EVIDENCE`。
