# ADR 0012：部署指定管理员可持久保存一份加密供应商凭据

- 状态：已接受
- 日期：2026-08-03
- 负责人：EventShock Lab 工程团队

## 背景

ADR 0006 规定 BYOK 只保存在会话级内存。这仍是普通用户最小化秘密暴露面的正确默认值，但唯一的项目运营管理员需要在服务器重启、退出登录和跨浏览器使用后继续运行已批准的外部模型流程。要求该管理员每次重新粘贴密钥会增加演示中断、复制粘贴泄漏和操作失误风险。

把明文 API Key 写入 SQLite、浏览器存储、日志、审计详情、导出、仓库或普通环境变量不可接受。与此同时，任何“服务器持久保存但连服务器运营者都无法接触”的说法也不真实：应用必须在调用供应商时取得明文 Bearer 凭据，主机 root 和 Docker 管理员也控制运行环境。

## 决策

保留 ADR 0006 作为所有普通用户的唯一凭据模式。只有 `EVENTSHOCK_ADMIN_EMAIL` 指定的唯一管理员账号可以在已经认证的前端中明确选择持久保存。普通管理员角色、普通用户和其他账号都不能创建、读取、使用、替换或删除这份持久凭据。

持久凭据采用以下边界：

- 服务器使用 Fernet 认证加密；独立主密钥由 `EVENTSHOCK_ADMIN_API_KEY_ENCRYPTION_KEY_FILE` 指向容器内只读文件 `/run/secrets/eventshock/admin-api-key-encryption-key`。
- 宿主机主密钥固定保存在 `/opt/eventshock/shared/secrets/admin-api-key-encryption-key`，由 `root:10001` 持有并设置为 `0440`。真实值不得进入 Git、镜像、Compose 环境变量或部署日志。
- SQLite 表 `auth_persistent_llm_credentials` 只保存指定管理员所有者、供应商/模型等有限元数据和认证加密密文，不保存明文 API Key。数据库备份可以包含密文，但不得与主密钥作为同一份无边界备份分发。
- 前端和 API 只返回是否已配置、供应商、模型、掩码提示和更新时间等非秘密状态；任何读取接口都不得返回或恢复完整 Key。
- 管理员必须显式选择持久模式；临时保存仍是默认。保存、替换与删除前还必须重新输入当前管理员密码完成高风险操作身份复验，并按账号与来源地址分别限制为每小时最多 5 次尝试。替换操作覆盖旧密文，删除或账户删除移除密文，相关审计只记录动作和非秘密元数据。
- 明文 API Key 不得进入浏览器持久存储、URL、请求日志、异常正文、审计详情、AI 对话、缓存键、实验/研究快照、账户导出或实验导出。
- 供应商调用时，后端只在必要的进程内路径短暂解密并复用现有固定端点、费用、Schema 和动作权限门禁。持久保存不会扩大模型工具权限或绕过用户确认。
- 主密钥缺失、格式错误、密文认证失败或所有者不匹配时必须失败关闭，不得回退为返回密文、猜测明文或静默使用其他账号凭据。纯规则实验完全不读取凭据；混合模式运行期凭据故障只能按已声明策略明确降级，或以可重试凭据错误终止，不得伪装成仿真器故障。

## 信任边界

该设计提供静态数据加密，不提供端到端加密、硬件 Secret Vault 或“只有账号持有人技术上可知”的保证。以下主体仍在信任边界内：

- 能读取宿主机 Secret 文件或控制备份的 root 用户与获授权运维人员；
- 能控制容器、挂载、调试器或进程内存的 Docker 管理员；
- 必须解密并构造供应商 Authorization Header 的运行中应用进程；
- 能在应用进程内执行的恶意依赖或成功利用应用漏洞的攻击者。

因此，数据库或数据库备份单独泄露不应直接暴露明文，但数据库与主密钥同时泄露、主机完全失陷或应用进程被控制仍可导致凭据泄漏。管理员应使用可撤销、最小权限、有账单限额和独立用量监控的供应商 Key。

## 被否决的方案

- **为所有账号开放持久 Key**：扩大多租户秘密存储、授权、恢复和事件响应面，不符合当前需求。
- **SQLite 明文或可逆混淆**：数据库、备份和诊断读取会直接暴露凭据。
- **浏览器 `localStorage`、IndexedDB 或 Cookie 保存**：页面脚本、扩展和共享设备可读取，且违背现有浏览器边界。
- **把供应商 Key 写入服务器 Secret 文件**：难以让管理员从产品内安全替换/删除，也会把业务凭据与部署配置生命周期混在一起。
- **使用认证主密钥直接加密而不分离**：扩大同一秘密的用途与轮换影响，违反密钥分离原则。
- **宣称运营方无法访问**：与服务器端供应商调用的技术事实矛盾，会形成误导性安全承诺。

## 后果

指定管理员可以跨登出、浏览器和服务重启复用凭据，普通用户的临时 BYOK 风险面不变。代价是应用新增一个高价值静态秘密、一个加密数据表和主密钥备份/轮换责任；主密钥丢失会使现有密文不可恢复，主密钥泄露则要求同时轮换供应商 Key。

该变化属于条款和隐私披露的实质变更。条款版本提升为 `2026-08-03-v3`，已有用户必须在继续使用需登录功能前重新明确接受；账户导出和实验导出继续排除供应商凭据。

## 验证与复审

自动化测试必须覆盖：普通用户拒绝持久模式、非指定管理员拒绝、显式保存/重启恢复/替换/删除、账号所有者隔离、错误主密钥和篡改密文失败关闭、API 永不回显明文，以及数据库/日志/审计/账户导出/实验导出不出现明文。部署测试必须验证主密钥文件的固定路径、所有者、权限、格式与只读挂载。

上线前还需要人工检查服务器日志、SQLite/WAL、备份、Crash Dump、容器挂载、供应商控制台与撤销流程。独立主机安全审查、密钥轮换演练和泄漏事件演练状态继续为 `PENDING_HUMAN_EVIDENCE`。
