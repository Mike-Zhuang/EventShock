# ADR 0001：以簿中静置订单价格作为成交价

- 状态：当前 MVP 已接受
- 日期：2026-07-15
- 负责人：EventShock Lab 工程团队

## 背景

限价订单簿在新订单与已有订单交叉时需要唯一、可重放的成交价规则。如果成交价交给语言模型、随机过程或运行时临时判断，相同输入可能产生不同账本，也无法解释价格来自哪一笔订单。

## 决策

成交价始终采用簿中静置订单的 `priceTicks`。新到达订单只决定是否与该价格交叉以及可成交数量；撮合优先级按价格、时间和稳定标识符确定。账本、持仓和成交事件只消费撮合引擎产生的结果，不允许其他组件覆盖成交价。

## 被否决的方案

- 使用新到达订单价格：会改变标准价格优先语义，并使主动方能够不必要地决定成交价。
- 使用买卖限价中点：中点可能不在合法 tick 上，也不对应真实挂单。
- 由 LLM 生成成交价：不可复现，并越过认知层与市场机制层的边界。

## 后果

优点是撮合确定、易于审计，并能在 matched-seed 实验中稳定重放。代价是当前模型没有交易所特有的开盘、收盘、竞价、隐藏订单或价格改善规则；这些能力必须作为显式的新市场机制加入，不能暗中改变本规则。

## 验证与复审

自动化测试应覆盖买卖两侧、部分成交、同价时间优先和重放一致性。将模拟成交特征与真实交易所微观结构进行专家级校准的证据状态为 `PENDING_HUMAN_EVIDENCE`，因此本决策不构成真实交易所规则认证。
