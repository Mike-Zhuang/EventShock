# ADR 0007：MVP 控制面采用 SQLite

- 状态：当前 MVP 已接受
- 日期：2026-07-15
- 负责人：EventShock Lab 工程团队

## 背景

单服务器课堂 MVP 需要保存事件包元数据、实验配置、运行状态和导出索引，但资源有限，也不需要一开始承担外部数据库的运维成本。模拟计算和大体积结果不应全部塞进控制面数据库。

## 决策

使用 SQLite 作为单实例控制面数据库，启用 WAL、外键、busy timeout 和进程内写锁。每次操作独立获取连接，不共享跨线程游标。数据库只保存结构化控制记录和必要索引；大文件导出使用受控目录。API 会话标识用于关联资源，但不宣称是完整用户认证。

## 被否决的方案

- 立即引入 PostgreSQL：增加配置、备份和凭据管理成本，超出单实例 MVP 所需。
- 纯内存状态：服务器重启后实验和导出索引全部丢失。
- 将所有模拟轨迹存入单表：会扩大锁竞争、数据库文件和迁移风险。

## 后果

部署简单、备份直接，适合低并发单服务器。代价是写并发、水平扩展、细粒度权限和高可用能力有限；多个应用副本不能依赖进程内锁协调写入。扩展到真实多用户服务前必须重新评估数据库与身份架构。

## 验证与复审

自动化测试应覆盖外键、并发失败语义、会话隔离和重启恢复。负载上限、备份恢复演练及多用户安全评估状态为 `PENDING_HUMAN_EVIDENCE`。
