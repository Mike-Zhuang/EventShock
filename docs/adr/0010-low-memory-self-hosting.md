# ADR 0010：采用低内存单服务器自托管架构

- 状态：当前 MVP 已接受
- 日期：2026-07-15
- 负责人：EventShock Lab 工程团队

## 背景

项目需要部署到资源有限的自有服务器，并通过 `eventshock.mikezhuang.cn` 提供 HTTPS 访问。服务器初始环境较少，因此部署必须可重复、限制资源并减少宿主机依赖。

## 决策

使用容器化单实例应用加 Caddy 反向代理。应用基础镜像锁定 CPython 3.12.13 的审核 digest，以非 root 用户运行，根文件系统只读，只给 `/data` 可写卷；删除 Linux capabilities，启用 `no-new-privileges`，并设置 CPU、内存和 PID 上限。Caddy 负责 TLS、HTTP 到 HTTPS 重定向和安全响应头。SQLite、缓存与导出位于受控数据卷，服务不承诺高可用。

## 被否决的方案

- 直接在宿主机安装完整运行环境：版本漂移和回滚成本更高。
- Kubernetes：对单机课堂 MVP 的资源和运维开销过大。
- 多进程水平扩展：当前内存 BYOK 会话、SQLite 写锁和本地文件导出不支持透明扩展。

## 后果

部署依赖少、资源上限明确，并能通过镜像重建。代价是单点故障、冷启动、有限并发以及本地卷备份责任；外部 LLM 网络延迟仍可能主导响应时间。扩容前必须把会话、数据库、缓存和对象文件迁移到支持多实例的服务。

## 验证与复审

部署验证应检查容器健康、只读文件系统、非 root 身份、资源限制、TLS 和重启恢复。实际峰值负载、灾难恢复、渗透测试和持续运维演练状态为 `PENDING_HUMAN_EVIDENCE`。
